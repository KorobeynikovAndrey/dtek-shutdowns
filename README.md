# DTEK shutdowns — GPV4.2

Автоматическая задача каждый час проверяет графики отключений на https://www.dtek-dnem.com.ua/ua/shutdowns и сохраняет их в этот репозиторий.

## Источник

- Объект страницы: `DisconSchedule.fact`.
- Даты и почасовые состояния: `fact.data`.
- Группа: `GPV4.2`.
- Время публикации обновления: `fact.update`.
- Ключи `fact.data` — Unix timestamp в секундах; даты определяются в часовом поясе `Europe/Kyiv`.
- Извлекать только фактически опубликованные графики за сегодня и завтра. Не придумывать отсутствующие данные.

## Файлы

```text
today.json
tomorrow.json
2026/
  11/
    06.json
    07.json
```

- `today.json` — график на текущую календарную дату.
- `tomorrow.json` — график на следующую календарную дату, если он опубликован. Если графика нет, файл должен отсутствовать.
- `YYYY/MM/DD.json` — график на конкретную дату; один файл на день. Каталоги `YYYY` и `MM` создаются по мере появления данных.
- Когда график изменяется, обновляются соответствующий файл в корне и файл за дату в архиве. Архив за прошлые дни не удаляется.
- История всех изменений в течение дня хранится в коммитах GitHub.

## Формат JSON

Одинаков для корневых и архивных файлов:

```json
{
  "group": "GPV4.2",
  "update": "<значение fact.update>",
  "data": {
    "<Unix timestamp даты>": {
      "1": "no",
      "2": "yes"
    }
  }
}
```

В `data` каждого файла ровно одна дата и все 24 опубликованных почасовых значения. Значения `yes`, `no`, `first`, `second` сохраняются без преобразования.

## Правила обновления

1. Получить свежие данные страницы, а не устаревший кэш или поисковый фрагмент; извлечь `DisconSchedule.fact.data` и `fact.update`.
2. Определить сегодня и завтра по `Europe/Kyiv`, выбрать для них `GPV4.2`.
3. Сравнить с файлами в GitHub. Создавать или обновлять файлы только при фактических изменениях данных или отметки `update`.
4. Когда меняется дата, актуализировать `today.json` и `tomorrow.json`. При подтверждённом отсутствии опубликованного графика на завтра удалить `tomorrow.json`; соответствующие архивные файлы не удалять.
5. Если данные страницы не удалось достоверно получить или разобрать, не изменять файлы.
6. О новой публикации или ошибке сообщать; при отсутствии изменений уведомление не требуется.
